所有路由的 `tau` 都来自有限 v1 hard negative 的 nearest-rank Q95，并使用严格比较 `cosine > tau`：两个专用 embedding 为 100/100 个有限观察，五个 Qwen 路由为 98/100 个有限观察。

## 1. 评分 bug，还是有效失败？

确认是**有效的表示质量失败**，不支持评分或配对 bug 的解释。

- 七路各有 100/100 个 v2 正例；每一路的 `positive.above_tau`、`positive.in_exact_top_k`、`positive.matched_candidate` 和 `positive.qualified` 都是 0。
- 每一路的 100 个正例失败都含 `below_tau`。`_route_quality_result` 先计算目标余弦并应用严格阈值，再通过 exact oracle 求 top-K；因此 `outside_exact_top_k` 与 `candidate_mismatch` 在这里是阈值淘汰的下游结果，不是独立的配对证据。
- 每一路被报告为失败的 hard negative 都在 `tau` 以上，且其 `target_above_tau` 数与 `target_in_exact_top_k` 数相同（6--15）。这与代码的阈值方向和 exact-oracle 行为一致。

因此，AC-112 的 `seven_route_all_fail` 是“高 Q95 下全部正例 `below_tau`”的真实结果；这不等于已经识别出唯一的表示机理。

## 3. 共同模式与分裂

共同模式：七个候选条件表示都使用同一类“最后 64 字符加当前候选”的无分隔序列化，均以 v1 HN Q95 校准，并在 v2 出现 0/100 正例越过各自阈值。两个独立 embedding 与五个 Qwen span/control/projection 变体没有形成例外，故失败不能归因于某一个 Qwen 层、池化或投影实现。

分裂：专用 embedding 的 `tau` 为 0.936393--0.960812，HN no-evidence 为 0.85--0.92；Qwen 路由的 `tau` 为 0.983588--0.996644，HN no-evidence 为 0.90--0.94。Qwen 路由的阈值更接近 1，且 HN 仍有 6--10 个超过阈值；BGE-M3 的 HN 失败最多（15），而 Qwen3 embedding 最少（8）。这些差异改变失败强度，不改变“所有正例先于 top-K 被阈值排除”的共同结果。

## 4. 机理候选（按现有证据）

1. **v1--v2 的可分性或校准分布错位（其他）**：证据最强。每一路的 v2 正例整体在其 v1 HN Q95 下方，而已报告的 v2 HN 处在阈值上方。工件证明了这个分布关系，不能仅凭它判断错位来自模型、基准语义还是表示对象。
2. **Q95 阈值在 HN 已很高时过紧**：直接把上述关系转为全灭。它是近端解释，不是“应降低 tau”的结论；已有 6--15 个 HN 超过 tau，降低阈值会改变 HN 误证据风险。
3. **候选条件对象仍主要由上文驱动**：中等支持。跨两个专用 embedding、多个层、池化控制和投影的一致 0/100 指向共享对象，而非单一模型实现；现有工件没有候选贡献消融，不能确认这个原因。
4. **无分隔拼接坍缩**：中低支持。它是所有路由共享的固定序列化，因而是可检验的具体假设；但没有带分隔的预声明对照，当前数字无法把它与候选信号不足区分开。
5. **exact top-K 或 distractor 配置**：不支持其作为首要原因。所有正例在进入 exact top-K 前已 `below_tau`；K 或 distractor 可能影响阈值之后的保留，但无法解释七路 0/100 的 `above_tau`。

## 5. 不应做什么，以及供 owner 选择的方向

不进行第二次 v2 shot：已接受的 `seven_route_all_fail` 是该轮的终态。也不启动 #113：没有任何 v2-pass 路由，live `gamma` 保持 0。

以下只是可能的后续研究或实现方向，不是本诊断批准的下一张 ticket：

1. 冻结一个新的表示假设和新的验收集版本，预先声明结构化或带分隔的候选序列化对照；不得复用本次 v2 结果调参后重跑。
2. 用独立的受控基准诊断候选贡献，例如固定上文的候选替换比较，以区分“上文主导”和“拼接边界”两种假设。
3. 单独研究 v1 HN Q95 与新验收集的校准可分性；任何阈值策略变更都应有新的、预冻结的验收证据，而非对本次 v2 回调。

**给 owner 的决策建议：**将本轮视为已完成的有效淘汰，维持 `gamma=0` 并保持 #113 停止。若要继续，只选择一个新的、可区分上述机理的假设，连同全新的冻结验收版本一起再作决定；本报告不授权降低阈值、改动 payload 或重跑现有 v2。
